# LABDAM 통합 로그인 검증 — 2026-10-16 (KST)


> **2026-10-16 최신 운영·실계정 검증:** [RELEASE-ACCEPTANCE-20261016.md](RELEASE-ACCEPTANCE-20261016.md)를 우선 확인하세요. 아래 내용은 작성 당시의 준비/검증 기록이며, 신규 r3 시험 Worker 배포와 현장 관리자·회원 승인·철회 시험 완료 상태를 반영하지 않은 문장이 포함됩니다.

## 결과와 검증 범위

`feature/free-google-approval-auth-20261014`를 원격 `784dc0a`까지 fast-forward로 동기화했다. 로컬 추적 파일 변경은 없었으며 별도 `labinsight-source/` 체크아웃은 보존했다. 보호 번들은 기존 CI와 같은 LabInsight 커밋 `7a5c024df3e5bc41f256b8f935cb932f1ad2705d`로 다시 빌드했다.

**로컬 인증·권한 검증은 통과했다. 수정본은 아직 Cloudflare에 배포하지 않았으므로 실제 Google 계정 로그인 성공을 주장하지 않는다.** 현재 원격 Worker의 익명 게이트 검사만 완료했다. 시험 배포도 사용자의 사전 승인이 필요하다.

## 코드 변경

- `784dc0a`의 Google token/JWKS `redirect: "manual"` 및 모든 3xx 거부를 유지했다. 로컬 workerd에서 실제 fetch 경로를 실행하고 외부 리디렉션을 따르지 않는 것을 검증했다.
- Google token/JWKS 요청에 각각 10초 타임아웃을 추가했다. 네트워크 실패와 오류 응답의 원문·인증 코드·토큰·비밀값을 기록하지 않고 기존 고정 분류만 기록한다.
- OIDC 헤더·페이로드가 null, 배열, 원시값인 경우 401로 거부한다. null token 응답도 내부 TypeError 없이 거부한다.
- 실패한 OAuth 콜백에서 state 쿠키를 삭제한다. 토큰 교환 전에 소비한 state는 실패 후에도 재사용할 수 없다.
- 회원 정보 갱신·세션 발급·회원 상태 조회를 D1 `batch`로 묶었다. 세션 저장 실패 시 부분 가입이 남지 않으며 승인/철회가 중간에 끼어들지 않는다.
- 관리자 심사의 세션 삭제·상태 갱신도 하나의 D1 `batch`로 묶었다. 기존 두 요청 사이의 경쟁 조건을 제거하고 실패 시 전체를 롤백한다. 첫 pending → approved에서는 현재 신청 세션을 유지한다. 철회/거절 및 rejected → approved에서는 기존 세션을 삭제한다.
- Linux `/tmp`를 가정한 사전 검사 테스트를 플랫폼 임시 경로로 수정했다. Windows에서는 junction으로 동일한 링크 탈출 거부 검사를 수행한다. Python/Chromium 실행 경로를 환경변수로 지정할 수 있게 했다.
- 로컬 workerd·D1·실제 정적 자원 바인딩 통합 테스트를 CI에 추가했다. Miniflare `5.20261012.0-beta`와 종속 workerd를 lockfile로 고정했다. 이는 검증에 사용한 Wrangler 4.151.0의 런타임 계열이며 배포 Worker에 포함되지 않는 테스트 전용 의존성이다.

D1 batch의 순차 실행 및 실패 시 전체 롤백은 [Cloudflare 공식 문서](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch)에 근거하며, 테스트에서는 SQL 트리거로 실패를 유도해 실제 로컬 D1에서 확인했다. DB 스키마 변경이나 새 마이그레이션은 필요하지 않다.

초기 실패 원인은 LabInsight 소스 환경변수 누락, Linux 전용 `/tmp` 가정, Windows 샌드박스의 junction/loopback 제한이었다. 소스 경로와 이식성을 수정하고 필요한 로컬 실행 권한으로 재검사했다. 최종 검사에서 건너뛴 테스트는 없다.

첫 GitHub CI에서는 `npm --prefix`가 작업 디렉터리를 테스트 폴더로 바꾸어 workerd의 기본 모듈 루트 밖에 `worker.mjs`가 위치하는 문제가 발견됐다. `modulesRoot`를 실제 Worker 디렉터리로 명시해 실행 위치와 무관하게 로드하도록 수정했다. 검사 자체를 생략하거나 운영 코드를 완화하지 않았다.

로컬 통합 테스트는 다음을 확인한다.

1. 가상 Google 서명 토큰 → 신규 pending 회원 → 관리자 승인 → **동일 쿠키로 `/` 및 `/labinsight/` 이용**.
2. pending/rejected 상태에서 보호 JS 접근 거부. 철회 후 다음 요청부터 차단. 재승인해도 삭제된 쿠키는 복구되지 않음.
3. 동시 승인·철회 요청이 있어도 삭제된 세션이 되살아나지 않음.
4. 관리자 상태 갱신 실패 시 세션 삭제도 롤백. 로그인 세션 발급 실패 시 회원 생성도 롤백.
5. token/JWKS 리디렉션 차단, 콜백 재사용 거부, 오류 시 state 쿠키 삭제.
6. 세션 만료, 일반 회원의 관리자 API 거부, CSRF 거부, 로그아웃, 탈퇴 후 서버 세션 제거.
7. 실제 자원 바인딩 앞에서 익명 차단, 공개 가입 안내만 허용, Worker 번들에서 Caffeine Atlas 제외.

## 원격 읽기 전용 검사

검사 대상: `https://labdam-free-approval.jleegenomics.workers.dev` 및 기존 Pages 공개 URL. 쿠키 없이 GET만 요청했으며 `/auth/start`나 인증 콜백은 실행하지 않았다.

- 시험 Worker 익명 게이트: **21/21 통과**. 안내 200, 보호 HTML 303, 보호 JS/CSS/API 401, Worker의 `/caffeine-atlas/` 404. 이 21개에는 아래 Caffeine Atlas 4개 검사가 포함된다.
- Caffeine Atlas 고정 URL 4개: **전부 익명 200**. 루트, `caffeine-sensitivity-app/analyzer.html`, `privacy.html`, `terms.html`. 주소 변경 없음. 물리 포스터 QR 스캔은 별도 미검증.
- 기존 LABDAM/LabInsight Pages 18개: **모두 익명 200 (EXPOSED)**. 원래 공개 사이트를 유지하라는 조건에 따라 변경하지 않았다. 이 직접 접근 경로가 유지되는 동안 서비스 전체를 승인제 전용으로 전환했다고 말할 수 없다.

## 재현

저장소 루트에서 테스트 의존성을 설치하고, 위에 고정한 LabInsight 체크아웃을 `LABINSIGHT_SOURCE`로 지정한다. `build.mjs`는 기존 `free-auth/dist` 덮어쓰기를 거부하므로 기존 출력은 먼저 안전하게 별도 보관한다.

```sh
npm ci --no-audit --no-fund
npm ci --prefix free-auth/tests/runtime --no-audit --no-fund
node free-auth/build.mjs
node --test tests/*.test.cjs free-auth/tests/*.test.cjs free-auth/tests/*.test.mjs
npm test --prefix free-auth/tests/runtime
python3 -m unittest discover -s free-auth/tests -p test_schema.py -v
node free-auth/scripts/preflight-static.mjs --require-real-d1
npx playwright test --config free-auth/playwright.config.cjs
```

Windows에서는 `PYTHON`에 Python 실행 파일, 필요 시 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`에 설치된 Chromium 실행 파일을 지정할 수 있다. 기본 CI는 Playwright의 고정 Chromium을 설치해 사용한다. 위 명령에는 원격 배포·D1 수정이 없다.

## 승인 후 수행할 검증

1. 이 PR의 변경과 테스트 결과 확인 후 **시험 Worker `labdam-free-approval`만 재배포** 승인. 기존 origin/DB/Secrets/공개 Pages는 그대로 유지한다. `main` 병합 및 운영 전환은 별도 승인 대상이다.
2. Codex가 배포를 실행하고 배포 버전을 확인한다. Cloudflare 인증이 만료됐다면 사용자 로그인만 필요하다. 비밀값은 채팅이나 GitHub로 가져오지 않는다.
3. 사용자가 브라우저에서 관리자 Google 로그인을 완료한다. 실제 callback 성공, 세션 설정, 관리자 권한을 확인한다. 관리자 bootstrap 값과 최초 가입 상태는 실제 확인 전까지 미확정이다.
4. 별도 시험 계정으로 pending → 승인 → 두 서비스 접근 → 거절/철회 → 재승인 → 이전 세션 차단을 원격 검증한다. 실제 계정 상태 변경 범위와 대상은 사용자 확인이 필요하다. 만료 경계는 로컬 D1에서 이미 검증했으며 원격 세션 임의 조작은 하지 않는다.
5. 기존 Pages 접근 정책은 사용자의 별도 운영 결정이 필요하다. Caffeine Atlas QR 및 공개 주소는 유지한다.
6. 회원 개인정보 고지의 운영자·연락처·보관기간 확정이 남아 있다. 일반 preflight는 경고이며 정식 공개용 `--require-final-policy` 통과를 뜻하지 않는다.
