# LABDAM·LabInsight 회원가입 개인정보처리방침 최종 확정 체크리스트

작성일: 2026-10-16 / 상태: **검토 중, 공개용 법적 처리방침 최종본 아님**

기준: [개인정보 보호법 제30조](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1034265579), 개인정보보호위원회 [개인정보 처리방침 작성지침(2026.4.)](https://pipc.go.kr/np/cop/bbs/selectBoardList.do?bbsId=BS217&mCode=D010030020).

## 1. 운영자가 직접 확정할 정보 — 임의로 공개하지 않음

- [ ] **법적 개인정보처리자 명칭:** 본인 단독 운영이면 실제 책임 주체의 법적 명칭; 등록 사업자가 개인정보 처리를 결정한다면 해당 사업자 명칭. LABDAM은 서비스 브랜드명이므로 자동으로 법적 명칭으로 처리하지 않음.
- [ ] **개인정보 보호책임자 또는 담당 창구:** 실제 담당자(혹은 담당 조직), 요청을 처리할 수 있는 연락처. 공개 전 책임 주체가 확인해야 함.
- [ ] **비공개 민원 접수 이메일 또는 다른 안전한 방법:** 실제 수신 가능한 전용 이메일 권장. 회신·본인확인·처리 기한·접속 기록 관리 방법을 지정. 개인 학번 이메일/학교 이메일, 공개 GitHub Issue를 확인 없이 사용하지 않음.
- [ ] **회원정보 보유기준에 대한 운영 결정:** 아래 현재 보유 로직과 신규 자동 파기 계획 중 무엇을 유지·구현할지 선택.
- [ ] **Google / Cloudflare 이용 실태**: 제3자 제공·처리위탁·국외 이전의 법적 분류, 관련 국가·데이터센터 및 계약·DPA·이용자 고지 내용을 실제 서비스 계정에서 검증.
- [ ] **정책 시행일 및 이전 버전 변경 이력**, 권리 행사 대응/담당자 연결, 처리 불가능 시 연락 절차 확정.

## 2. 코드에서 확인한 현행 보유기간 — 이미 안내 문구에 반영

| 저장 자료 | 실제 코드와 DB의 기준 |
|---|---|
| 회원 Google sub, 이메일, 표시 이름, 가입 목적(선택), 승인 상태, 승인 담당자 식별자·시각 | 승인·대기·거절 모두 **자동 만료 없음**. 회원이 탈퇴하면 기본 회원 행과 관련 세션 삭제. 현재 운영 정보가 삭제 전까지 남을 수 있음 |
| 일회성 OAuth 상태 | 유효기간 **10분**, 소비 또는 정기 정리 |
| 로그인 세션 | 유효기간 **최대 7일**, 로그아웃·승인 철회·탈퇴 시 삭제, 만료 후 정기 정리 |
| 로그인 횟수 제한용 해시·윈도 | 생성 윈도 기준 **24시간을 초과**한 기록을 하루 한 번 정리. 정상 상황에서도 약 48시간까지 잔존 가능 |
| LabInsight / CarePath 검사 수치 | 회원 D1에는 저장 안 함. 사용 중 브라우저 탭 임시 저장, 사용자 삭제/로그아웃 시 정리 시도 |

근거 코드: `free-auth/worker.mjs`, `free-auth/migrations/0001_initial.sql`. Worker cron: `15 3 * * *` UTC. 서버 만료 이후 DB 물리 삭제는 작업 성공·시각에 따라 늦을 수 있음. Cloudflare 보조 처리 로그/백업 기간은 별도.

## 3. 추천 보유기간 개선안 (아직 구현·고지하지 않음)

- **승인 회원:** 서비스 이용 기간 동안 보관하고 회원 탈퇴 시 삭제. 법정 별도 보존 사유가 확인되면 해당 최소 항목과 기간을 구분.
- **승인 대기:** 예를 들어 마지막 신청·활동으로부터 **90일** 후 보안·사용자 고지를 포함한 자동 정리 검토.
- **거절 상태:** 예를 들어 거절 처리 후 **30일**이 지나면 최소 필요한 이력만 남기거나 자동 삭제 검토. 반복 악용 방지 등 정당한 목적과 필요성 검증.
- 현 시점 두 기간은 **법률이 정해 준 값이 아니며 운영 검토용 제안**입니다. 사용자가 동의하기 전에는 D1 삭제 스케줄·마이그레이션을 적용하지 않음.
- 선택한 보유기간을 실제로 적용하려면: 데이터 필드·만료 기준 설계 → 합성 D1 테스트 → 회원 알림/예외처리 → 만료 삭제 작업 → 수동 Worker 배포 → 데이터 삭제 기록 확인 순서가 필요. 기존 실제 회원 데이터를 예고 없이 삭제하지 않음.

## 4. 정식 정책 공개 이전 검증

`node free-auth/scripts/preflight-static.mjs --require-real-d1 --require-final-policy`는 최종 승인 전에 **실패해야 정상**입니다. 새 회원가입 개인정보 안내 HTML의 `policy-status=draft` 및 실제 미확정 운영자·문의처 때문에 정식 정책 검사를 차단합니다.

운영자가 명칭·연락처·기간·외부 제공자 검토를 마치고 실제 UI/운영 코드가 해당 내용과 일치할 때만 승인 메타 태그를 `final`로 바꾸고 배포합니다. 자동검사 성공 자체는 법적 준수 인증이 아니며 필요한 법률 검토는 별도 수행합니다.

## 5. Caffeine Atlas는 별도

Caffeine Atlas의 공개 QR과 주소는 유지. 해당 공개 서비스의 별도 Google Sheets/유전자형 처리 정책과 보유기간 검토는 이 **회원 인증 DB의 개인정보처리방침**으로 해결되지 않습니다.
