## 이어하기 규칙

- 같은 Mac에서 순서대로 작업할 때는 이전 도구의 수정이 끝난 폴더/브랜치를
  다음 도구가 그대로 열 수 있습니다. 미커밋 변경은 먼저 확인하고 보존합니다.
- 동시에 작업할 때는 각자 별도 worktree/브랜치를 사용합니다.
- 진행 중인 작업은 그 작업 브랜치에서 이어받습니다. 아직 병합하지 않은 변경을
  이어받을 때 새로 main만 내려받아 시작하지 않습니다.
- 다른 PC로 옮길 때는 의도한 변경의 커밋·push와 인계 문서 갱신이 필요합니다.
- 비공개 앱의 상세 소스·진행 상태는 해당 비공개 저장소에 기록합니다.

## 다음 작업

1. Mac의 기존 LABDAM 프로젝트에서 로컬 폴더·터미널에 접근할 수 있는 Work를
   엽니다. 기존 클라우드 작업에 로컬 접근이 없으면 같은 프로젝트의 로컬 작업에서
   이 인계를 이어받습니다. 실제 폴더·origin·브랜치와 진행 중인 수정을 먼저
   확인하고 기존 작업을 보존하면서 위 작업 브랜치의 최신 커밋을 가져옵니다.
2. 포털 루트에서 `node developer/ai-doctor.mjs`를 실행합니다. JSON의 설치,
   버전, 작업 브랜치와 작업트리 상태를 확인합니다. 기본 실행은 모델 요청을
   하지 않으며 종료 코드 `0`도 각 CLI의 준비 완료를 뜻하지 않습니다.
3. `node developer/ai-doctor.mjs --probe-claude`로 기존 Claude 로그인 경로와
   짧은 실제 응답을 검사합니다. `claudeProbe.state: passed`와 요청 시각,
   버전, 인증 방식만 기록합니다. 토큰·계정정보·원본 오류는 올리지 않습니다.
   차단/실패 시 `reason`에 해당하는 조건을 확인합니다. 옵션을 제거하거나
   API 인증으로 전환하는 재시도는 하지 않습니다.
4. 지정한 코드 변경을 대상으로 검토 전용 호출을 구현·검증합니다. Claude의
   짧은 응답 성공은 코드 검토 성공과 다릅니다. Google `agy`는 아직 설치·도움말
   확인만 자동화했으므로 실제 설치본의 인증·권한 제한을 확인한 뒤 요청합니다.
5. Codex가 응답을 받아 원본과 대조하고, 필요한 수정과 관련 검사를 수행하는
   흐름을 검증한 뒤 그 결과를 이 인계 문서나 PR에 기록합니다.

## 도구 관련 결정

- Claude는 승인된 기존 구독 로그인을 사용합니다.
- Google 개인 구독 경로는 Antigravity CLI `agy`입니다. 기존 Gemini CLI 개인
  구독 지원 종료에 대한 공식 전환 안내는 협업 가이드에 연결되어 있습니다.
- 비대화형 명령이 있다는 사실을 읽기 전용 보장의 근거로 삼지 않습니다.
  Antigravity는 헤드리스에서도 활성 작업 폴더 내부 쓰기가 기본 허용됩니다.
- API 키·구독 변경·유료 초과 사용으로 자동 전환하지 않습니다.
- 새 협업 저장소나 중복 PR을 만들지 않고 현재 초안을 이어갑니다.

## 증거와 제한

GitHub 소스와 공식 CLI 문서를 확인하고 점검 도구를 모의 CLI로 검사했습니다.
현재 실행 환경에는 사용자 Mac 작업 폴더와 CLI 로그인 세션이 연결되어 있지
않습니다. 이 세션에서 로컬 Work로 직접 전환하는 도구도 없고 연결 브라우저
접근도 되지 않아, 사용자 기기의 실제 호출은 실행하지 못했습니다. 따라서
'세 AI가 이미 자동으로 함께 실행된다'고 보고할 근거는 아직 없습니다.

이번 클라우드 개발 환경에서 `node tests/ai-doctor.test.cjs`로 모의 검사 15개가
모두 통과했습니다. 기본 진단 실행도 정상 JSON을 만들고 모델 요청 없이 끝났습니다.
이는 사용자 Mac의 검사 결과가 아닙니다. CI는 Node 22에서
`node --test tests/workspace-bootstrap.test.cjs tests/ai-doctor.test.cjs`를 실행합니다.

실제 기기의 모델 요청 검사는 위 3번 명령으로 별도 수행합니다. 기본 진단·명시적 확인 요청의
결과 형식과 제한은 [협업 안내](../ai-collaboration.md#사용자-기기에서-연결-점검)에
기록했습니다.

이 문서의 목적은 다음 도구가 같은 지점에서 계속하도록 하는 것입니다. 외부
AI 호출과 사용자 기기의 실제 검증이 끝나면 미실행/확인 필요 항목을 실제 결과로
갱신하세요.
